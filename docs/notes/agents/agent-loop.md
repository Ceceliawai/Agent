# Agent Loop：从感知到行动

Agent Loop 是智能体持续接收环境信息、判断下一步动作并执行反馈的过程。与一次普通的模型调用相比，它最重要的特征是：模型输出可以改变环境，而环境变化又会进入下一轮推理。

## 1. 感知：整理当前状态

感知阶段负责把用户输入、历史消息、工具结果和运行环境整理成模型能够理解的上下文。

```text
用户目标 + 对话历史 + 工具结果 + 系统约束
                    ↓
                模型上下文
```

#### 四级标题

这一阶段的重点不是收集尽可能多的信息，而是保留对当前决策真正有帮助的状态。上下文过长会增加成本，也可能让关键约束变得不明显。

## 2. 决策：选择下一步动作

模型根据当前上下文判断任务是否已经完成，或者选择下一项动作：

- 直接回答用户；
- 调用一个工具；
- 请求必要的补充信息；
- 将复杂任务拆成后续步骤。

一个可靠的决策层需要同时考虑目标、约束和已有证据。模型不能把“看起来合理”当作“已经验证”。

## 3. 行动：执行并观察结果

执行器将模型生成的工具调用转换成真实操作，例如读取文件、运行命令或请求外部服务。执行结果不会自动等于任务成功，它必须重新进入下一轮感知阶段。

```ts
while (!task.completed) {
  const context = observe(task)
  const action = await decide(context)
  const result = await execute(action)
  task = update(task, result)
}
```

## 4. 闭环的关键

Agent 的可靠性通常不只取决于模型能力，还取决于闭环是否完整：

1. 工具结果是否被准确记录；
2. 失败是否会触发新的判断；
3. 完成条件是否可以验证；
4. 循环是否具有步数、时间或成本边界。

因此，一个实用的 Agent 系统更接近受约束的状态机，而不是无限制地反复调用大语言模型。
